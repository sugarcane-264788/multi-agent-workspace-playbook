# 子代理派活与回收

版本：2026-10-23（v1）

## 什么时候用

- 要读一堆文件、批量核对、查证冲突、审计过期表述。
- 用户说"派个代理""节约点上下文""让它去查"。
- 你自己要连续读 10+ 个文件才能出一个结论。

## 什么时候别用

- 写库、改文件、发信、重建索引：**永远主会话自己做**（否则台账必漏、索引必旧、播报没人发）。
- 只需读 1–3 个文件：直接读更省。
- 需要问用户才能定的事：子代理不能问人，会把猜测当结论。

## 派活模板

```
任务：只读审计，不改任何文件。
对象：<路径/文件清单>
判据：<什么算过期/冲突/不一致>
返回：一张表，列 `文件:行号 | 现在写的（原话） | 应该改成`；同一问题合并；≤15 行；
      最后一行写"未修改任何文件"。
时间上限：<N 分钟>
禁止：修改文件、发信、重建索引、安装依赖。
```

要点：
- 判据要**可判定**（"写的是 12 项而实际 13 项"可以；"看起来不对"不行）。
- 要求给**原话 + 行号**，否则你无法核。
- 回报设上限（行数/字数），否则等于没省上下文。

## 回收（干完必做）

1. 确认状态 `inactive`；
2. 裸 uuid 会话目录移到备份区 `<备份>\subagent-sessions-<日期>\`；
3. 清临时脚本/临时文件；
4. 回报里写「回收：<id> → <路径>」。

## 例子（真回收记录）

```
回收：<subagent-id> → <backup-dir>\kb-edit\subagent-sessions-20261023\
回收：61af9f7f-… → 同上
```

子代理真实回报的末行：

```
未修改任何文件。
```

## 验收

- 子代理回报含"未修改任何文件"，且带 `文件:行号`。
- 回收后活跃会话区无裸 uuid 目录；备份目录里能查到。
- 主会话没有因为派活而漏记账（写库仍在主会话）。

## 常见坑

- 派了写库的活 → 台账漏、索引旧、播报没人发。
- 判据模糊 → 回来一堆"建议"，你还要重读。
- 不设上限 → 回报比你自己读还长。
- 忘了回收 → 上下文与磁盘长期占着。
