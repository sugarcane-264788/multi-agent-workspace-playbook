# 分层自检

版本：2026-10-23（v2：补验收与例子）

## 什么时候用

- 用户说：体检、自检、别让库烂掉、接手验收、跑一下检查。
- 你改完一批东西，要证明"没改坏"。
- 新会话接手前，先跑一遍基线。

## 什么时候别用

- 单文件小改且没有自检脚本：手工看一眼就够。
- 只是想验证一段代码能跑：跑测试，不用四层自检。
- 库还没有自检脚本：先写第 1–3 项（骨架/编号/死链），别追求四层齐全。

## 四层

| 层 | 查什么 | 成本 | 频率 |
|---|---|---|---|
| 1 结构 | 目录骨架、编号唯一、死链、目录 README、修订记录格式 | 秒 | 每次改动 |
| 2 一致性 | 共用格改过是否播报、名册与盘上一致、索引不落后 | 秒 | 每次改动 |
| 3 机器层 | 快照 vs 盘上/名册/游标；schema 合规；纯 ASCII | 秒 | 收尾必跑 |
| 4 接手 | 真开一个新会话，只给接手语，看它卡在哪 | 分钟 | 改完接手文档 |

**别把 4 层塞进一个脚本**：前三层秒级、每次跑；第四层要真会话。

## 各项怎么落地

1. **目录骨架**：关键目录 + 每目录 README 存在。
2. **编号唯一**：`^N. ` / `^## N. ` 不重号不空号（历史重号用对照表过渡）。
3. **死链**：只扫活文档（跳过归档目录、收件箱/播报、索引、修订记录）；反引号里的 `.md` 才算；解析顺序＝绝对 → 工作区根 → 当前目录 → 库根；含 `<>`、空格、`NNNN`、`http` 的跳过。
4. **共用格播报**：`00-规范\*` 或共用资料目录里任一文件 mtime 晚于最新播报 → FAIL。
5. **名册一致**：AUTO 无重复、手工段 id 在 AUTO 段里、守护会话有目录且属工作区（"归档"只算提示）。
6. **索引不落后**：任一活文档 mtime 晚于索引 → FAIL。
7. **机器层对账**：会话数/箱数/未读合计/游标与盘上一致；schema 校验；键名 ASCII 小写下划线、值纯 ASCII、无 BOM。

## 判读：红了几项，是真坏还是在收尾

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 索引落后，落后的是**别的线刚改的文件** | 另一条线在收尾 | 等 30 秒或接着干，别替它 rebuild |
| 共用格未播报，指向别人刚改的文件 | 同上 | 同上 |
| 机器层 DRIFT（未读差几封） | 刚发/收信，快照没跟上 | 跑一次快照生成，再 doctor |
| 名册里某会话"已归档" | 侧栏隐藏，不等于服务停了 | 看心跳/日志；归档只当提示 |
| 死链只报历史目录里的旧文件名 | 历史文档不该进检查 | 把归档/收件箱/播报加入跳过 |
| 死链报"引用了还没建的文件" | 写文档时提前引用 | 建了再引，或去掉 `.md` |

原则：**看清楚是谁在什么时候改的，再动手**；修别人正在收尾造成的红 = 制造冲突。

## 例子（真输出）

```
[FAIL] 12 索引不落后
       - 索引落后，重新跑 kb_index.py：40-协作\_计划卡\2026-10-23-M16-….md
[FAIL] 3 死链
       - 40-协作\_计划卡\2026-10-23-M16-….md -> skills/x/SKILL.md
```

第一条：改完卡没重建索引 → 跑 `kb_index` 就好。
第二条：路径没带工作区前缀 → 改成 `交付物\…\skills\x\SKILL.md` 或去掉 `.md`。

## 验收

- `kb_check` 全 PASS；`--doctor` PASS（无 `[DRIFT]`）。
- 故意制造 1 个 FAIL（改一个文档不重建索引），确认脚本能报出来——**证明它真的在检查，不是空跑**。
- 第 4 层：新会话报告"卡住=无"。

## 新检查怎么加

1. 先有真实事故（哪次、哪步、什么症状）；
2. 检查必须自动跑、明确 FAIL/PASS；
3. 加进去同时写"假 FAIL 判读"，否则第一次误报就有人把检查关掉；
4. 改自检脚本本身也走卡 + 台账 + 验收。
