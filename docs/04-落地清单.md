# 落地清单：从零到能跑，90 分钟

> 目标：一个能容纳 3–6 个会话、共用一份真相、可接手、可回滚的协作库。
> 每一步都给"跑什么、看到什么算过"。**别跳步**——第 3 步（台账）没做，后面全部白搭。
> 环境：Windows + DSH；一个 Python（本项目用 DSH 自带 runtime）；全权档位一条会话负责搭。

## 0. 先想清楚三件事（5 分钟）

1. **有哪几条线**？每条线一个箱、一个角色、一块格子。少于 2 条线就别上这套，单会话 + 一个 README 更省。
2. **哪些事实是共用真相**？只给这些建文档与检查；私人草稿放各自的格子，别进索引。
3. **谁来写库**？必须只有一条线（通常是"维护线"）能写共用格、改索引、发播报。

## 1. 目录骨架（10 分钟）

```bash
WS=<workspace>
mkdir -p "$WS/协作库"/{00-规范,10-主对话,20-学习,30-邮件,40-协作/{_计划卡,_消息/{main,已处理/main,.cursors},_播报,_模板,交办,交办/已办},_索引.md}
```

约定：
- `00-规范/` 放规矩（01–09 张：环境、工具链、坑位、用户偏好、目录、文档规范、权限、外部编辑、自检方法）。
- `[角色]/` 一格一目录，一个主人。
- `40-协作/` 放共用机制：计划卡、信箱、播报、模板、交办。
- `_索引.md` 是生成物，放库根。

**验收**：`find 协作库 -maxdepth 2 -type d | sort` 与你画的结构一致。

## 2. 信箱（20 分钟，最难省的一步）

契约（先定契约再写代码）：

```
信封：_消息/<箱>/<YYYYmmdd-HHMMSS>-from-<发件人>.md
归档：_消息/已处理/<箱>/<同文件名>
游标：_消息/.cursors/<箱>  内容=最后归档的一个文件名（兼容 {"last": "..."}）
兜底：%TEMP%\dsh-mailbox\outbox\   （受限档位发不出时落这）
头四行：发件人/收件人/时间 + 「给：<会话名>」；正文可用 `error_code: XXX`
```

最小实现（一个文件，标准库，约 80 行）：

```python
import os, sys, time, shutil
BASE = r"<workspace>\<kb>\40-协作"
BOXES = {"main": os.path.join(BASE, "_消息", "main"),
         "email": os.path.join(BASE, "_消息", "email")}
LABEL = {"main": "主对话", "email": "邮件会话"}

def cur_path(box): return os.path.join(BASE, "_消息", ".cursors", box)

def cursor_of(box):
    p = cur_path(box)
    if not os.path.exists(p): return ""
    t = open(p, encoding="utf-8").read().strip()
    if t.startswith("{"):                      # 兼容受限会话写的 JSON 游标
        import json
        try: return json.loads(t).get("last", "")
        except Exception: return ""
    return t

def new_files(box):
    c = cursor_of(box); d = BOXES[box]
    names = sorted(x for x in os.listdir(d) if x.endswith(".md")) if os.path.isdir(d) else []
    return [n for n in names if n > c]          # 只取游标之后

def digest(box, peek=False):
    got = new_files(box)
    for n in got: print(open(os.path.join(BOXES[box], n), encoding="utf-8").read())
    if got and not peek:
        dst = os.path.join(BASE, "_消息", "已处理", box)
        os.makedirs(dst, exist_ok=True)
        for n in got: shutil.move(os.path.join(BOXES[box], n), os.path.join(dst, n))
        open(cur_path(box), "w", encoding="utf-8").write(got[-1])
    return got

def send(to, frm, text, code="OK"):
    ts = time.strftime("%Y%m%d-%H%M%S")
    name = f"{ts}-from-{frm}.md"               # ASCII 信封名，别用中文
    body = (f"发件人：{LABEL[frm]}\n收件人：{LABEL[to]}\n"
            f"时间：{time.strftime('%Y-%m-%d %H:%M')}\n给：{LABEL[to]}\n\n"
            f"error_code: {code}\n\n{text}\n")
    try:
        os.makedirs(BOXES[to], exist_ok=True)
        open(os.path.join(BOXES[to], name), "w", encoding="utf-8").write(body)
        print("已发：", os.path.join(BOXES[to], name))
    except OSError:                             # 受限档位：落兜底
        out = os.path.join(os.environ.get("TEMP", "/tmp"), "dsh-mailbox", "outbox")
        os.makedirs(out, exist_ok=True)
        open(os.path.join(out, name), "w", encoding="utf-8").write(body)
        print("已落兜底：", os.path.join(out, name))

def publish(frm, title, text):
    for b in BOXES:
        if b != frm: send(b, frm, f"【播报】{title}\n\n{text}")
```

**验收**（自己给自己发一封、读掉、再读）：
```bash
python mailbox.py send --to email --from main --text "测试"
python mailbox.py digest --for email        # 看到信；再跑一次应为空
```

规矩三条：一箱一线、读自己的箱＝收信、探别人的箱必须 `--peek`。

## 3. 名册 + 索引 + 台账 + 验收脚本（30 分钟，核心）

### 3.1 名册
两个段：

```markdown
<!-- AUTO-BEGIN -->
| 会话 id | 工作区 | 状态 | 目录 |
| --- | --- | --- | --- |
<!-- AUTO-END -->

| 角色 | 会话 id | 格子 | 说明 |
| --- | --- | --- | --- |
| 主对话 | `session-xxx` | 日常/调度 | … |
```

AUTO 段由脚本从运行时数据生成（DSH 的 `<agent-home>\storages\workspace.json`）；手工段只由校验器读，别让生成器碰。

### 3.2 索引
一个 30 行脚本：遍历活文档（跳过归档/消息/播报），取第一个 `# 标题` 和首段当"讲什么"，拼成 `| 文件 | 标题 | 讲什么 |` 表。**只此一个写入口。**

### 3.3 台账
`40-协作\_计划卡\ledger.tsv`：

```
ts	action	path	size	sha256	note
2026-10-23T20:01:02	edit	00-规范\05-目录结构.md	16971	<sha256>	补 09 行
```

`ledger.py add --path <相对库根> --action edit --note "<话>"`，脚本自己算 size/sha。

### 3.4 验收脚本 verify.py
- 读计划卡里所有 `- 文件：<路径>` 行 → 逐个查台账里是否有 **同 sha256** 的最新记录 → 缺则 FAIL；
- 跑卡里 ```` ```verify ```` 代码块里的命令（工作目录＝协作库根）→ 任一非 0 就 FAIL。

**验收**：改一个文件不记账 → `verify` 报"台账里没有记录"；记账后再改文件 → 报 sha 不一致。

## 4. 自检骨架（15 分钟）

先做 6 项，后面按事故加：

1. 目录骨架（关键目录 + README 都在）
2. 编号唯一（文档里 `^N. ` 不重复）
3. 死链（活文档反引号里的 `.md` 都能解析；跳过归档/消息/播报/索引/修订记录）
4. 目录 README
5. 修订记录能解析
6. 索引不落后（任一文档 mtime 晚于 `_索引.md` → FAIL）

**验收**：故意删一个 README、改一个文档不重建索引，各自报红。

## 5. 机器层薄快照（10 分钟，可后置）

- `_machine/schema.json` 先定（键名、枚举、pattern）。
- 生成器每次跑完顺手写 `sessions.json`、`mailbox.json`（纯 ASCII，带 `schema: 1`）。
- `read_state.py --sessions / --mailbox / --me / --codes / --doctor`：只吐几行。
- `--doctor` 对账：快照 vs 盘上会话目录 / 名册 / 游标，不一致退 1。

**注意**：快照**不是**新真相，是缓存；快照只能在"生成器跑过"时更新——所以要么让日常命令顺手更新，要么在做完操作后补跑。

## 6. 规范九张（15 分钟，先写骨架）

至少先写：`03-坑位清单`（踩过的坑，一条一个）、`04-硬规矩`（含工作协议）、`06-文档规范`（命名/改动/自检清单）、`09-自检与验收方法`（命令 + 判读）。其余可以后补。

## 7. 接手演练（10 分钟，这一步最值钱）

```
1. 写/改 启动语.md 与 接手交接.md（用 03-模板集.md 的接手语模板）
2. 真开一个新会话（agent CLI --headless 也行），只给它「接手语」
3. 看它卡在哪；把"卡住的地方"抄回文档再改
4. 直到新会话回报"卡住=无"
```

演练可以自动化（本项目做法）：`agent CLI --headless --json "<接手语>"`，解析 stdout 每行的 JSON（`type=session` 拿会话 id、`type=final` 拿最终文本）；需要设置 `DEEPSEEK_API_KEY`（从自己的桥/配置读）与 `AGENT_HOME`。

## 8. 迁移现有项目（不是从零时）

1. 先建信箱 + 台账 + 索引三件，**不改**现有文档；
2. 把现有文档"谁写"登记成格子表（只登记，不搬文件）；
3. 给每条线发一封播报解释新规矩；
4. 第一次真改动走一遍 卡 → 台账 → verify → 播报；
5. 稳定一周后再加自检项与机器层。

## 9. 什么时候不该上这套

- 只有一条会话、一个用户、资料少于 20 个文件：一个 README + 索引脚本足够。
- 团队里没人愿意维护规则：先别建规范，先建台账与自检——只有能自动执行的规矩才活得久。
- 需要频繁改结构的阶段：结构一周变三次时，先稳定结构再加机器层。
