# 经验清单：从真实事故蒸馏

> 每条都是我们一天之内**实际撞上**的，格式统一为「现象 → 根因 → 做法」。按主题分组，每组内按严重度排。
> 用法：搭协作库时当检查表读；出了问题按现象检索。

## A. 协作与信箱（多会话最容易死的地方）

### A1 信丢了，没有任何报错
- **现象**：给某条线发的两封信，那条线说没收到；箱里空着，日志正常。
- **根因**：两条线共用 `main` 箱、共用一个游标文件。谁先 `digest`，游标就推进到最新，另一条线下次只看"游标之后"，前面几封**永久不可见**，而且不报错。
- **做法**：一条线一个箱（`main`/`email`/`learn`/`prog`/`sched`/`other`/`kb`），游标按箱存；`publish` 广播时跳过发件人自己的箱；"给谁的"要写在正文第一行，不能靠箱子猜。

### A2 受限会话发的信永远到不了
- **现象**：某会话 `send` 报成功，对方箱里没有。
- **根因**：受限档位（本地文件写被沙箱挡）写不进协作库，`send` 走了兜底目录 `%TEMP%\dsh-mailbox\outbox\`；而收信方从没 `sweep` 过。
- **做法**：发信脚本失败时**读出完整路径并打印**；`digest` 时自动 `sweep`；兜底收件加"已收 N 封"计数；接手文档写明"兜底位置在哪、看到它意味着什么"。

### A3 读自己的箱把别人的信吃了
- **现象**：接手演练时新会话去"看看有没有信"，把别的线还没读的信归档了。
- **根因**：`digest --for X` 会归档并推进游标，这是收信语义，不是看一眼。
- **做法**：探别人的箱加 `--peek`（只看、不归档、不动游标）；文档里明写"读自己的箱＝收信，读别人的箱＝必须 `--peek`"。

### A4 信封名是中文，机器一碰就崩
- **现象**：排序、游标比较、跨平台传文件都会出怪问题；某箱未读永远是 0。
- **根因**：文件名带中文，且"游标"文件被受限会话用 JSON 写成 `{"last": "..."}`，而读游标的代码直接字符串比较。
- **做法**：信封名纯 ASCII：`<时间>-from-<发件人ascii>.md`、兜底 `from-fallback-*`；读游标同时兼容纯文件名与 `{"last":...}`；中文只留在正文。

### A5 播报没人看
- **现象**：改了共用格、发了播报，其他线该更新的没更新。
- **根因**：播报只有标题，没有"要做什么"。
- **做法**：播报固定四段——变了什么 / 影响谁 / 要做什么 / 证据在哪；跨格事实变更（规范、模板、工具、索引）必须在当轮播报，否则自检第 8 项直接红。

## B. 真相与索引（过期信息是慢性毒）

### B1 索引和现实漂了
- **现象**：按索引找文档，标题对不上，或者根本没有。
- **根因**：索引手工维护，两个会话各改各的。
- **做法**：索引只由 `kb_index.py` 生成，谁手改谁负责；自检加"索引不落后"一项（比对 mtime）。

### B2 名册手改后被自动段覆盖
- **现象**：手工补的会话信息，下次生成就没了。
- **根因**：脚本重写整张表。
- **做法**：名册分 AUTO 段（脚本生成，起止标记内）和手工段（只由校验器查、不由生成器写）。

### B3 文档里的路径全是死链
- **现象**：自检报死链，但文件明明存在。
- **根因**：死链检查有解析顺序（绝对路径 → 工作区根 → 当前目录 → 收件箱根），不同写法解析到不同地方；历史目录（归档、已处理消息）里的引用不该算。
- **做法**：死链检查只扫"活文档"（跳过归档、收件箱、播报、索引、修订记录）；反引号里的 `.md` 才算；写历史文件名不带 `.md` 后缀；公共根用 `..\工具\...` 这种相对写法最稳。

## C. 改动与验收（没有账就没有回滚）

### C1 "我以为他只改了一个文件"
- **现象**：一处改动带崩三处，事后不知道谁改的。
- **根因**：没有台账，或台账只记了部分文件。
- **做法**：台账一行一个文件（时间/动作/路径/大小/sha256/说明）；验收脚本按计划卡的"文件清单"核 sha256——**清单漏一个文件、或文件改完又被改，都会当场红**。

### C2 计划卡写了等于没写
- **现象**：卡里说改 A，实际改了 A+B+C。
- **根因**：卡没有"要改的文件清单"和可执行的验收命令。
- **做法**：卡固定六段：目标/范围/动作（含文件清单）/不做什么/验收命令块/回滚；卡外改动**先问后动**，真做了就写进卡里「偏差记录（如实记，不藏）」。

### C3 验收命令跑错地方
- **现象**：`verify` 报"找不到计划卡"。
- **根因**：参数是相对协作库根的路径，只给卡名不行。
- **做法**：`verify --card "40-协作\_计划卡\<卡名>.md"`；卡里的命令块以协作库根为工作目录。

## D. 人机双轨（把该给机器的给机器）

### D1 全库转 JSON 的冲动
- **现象**：为了让 AI 少读文件，想把八张规范全转 JSON。
- **根因**：误解了"AI 费力"——AI 费力的是**长文本**，不是格式；而人读的部分转成 JSON 后没人维护。
- **做法**：**只转薄快照**（会话/信箱这类字段化的状态），长文档保持 markdown；机器要的部分由 `read_state.py` 提炼成几行给主会话。项目大了再扩，别一步到位。

### D2 快照落后，别的会话按旧数字判断
- **现象**：某会话按"未读 87"行动，实际 92；对账一跑就红。
- **根因**：快照只在手动命令里更新，而日常操作（发信、归档、播报）不触发。
- **做法**：日常命令跑完顺手同步快照（`sync_snapshot()`），受限档位写不进就静默跳过；`--doctor` 把快照与盘上/名册对账，不一致退 1。

### D3 schema 自己写得随意
- **现象**：脚本换了字段名，下游全崩。
- **根因**：JSON 没有约定。
- **做法**：先写 `schema.json`（键名、枚举、pattern、必填），生成前后都校验；新字段先改 schema 再改代码；`json_lint` 进自检，保证键名 ASCII 小写下划线、值纯 ASCII、无 BOM。

## E. 权限与判据（别把"看起来像"当证据）

### E1 把"归档会话"当"停用服务"
- **现象**：桥会话被归档，自检报"桥挂了"，我们据此改了判据；事后实测 headless 桥照跑。
- **根因**：归档只影响侧栏显示与需要审批的交互；headless 不加载归档闸门插件。
- **做法**：判据只认**通道证据**（守护进程心跳、日志里有轮询、状态文件被更新）；"归档"降级为提示；这类误判写进否决账，防复发。

### E2 受限档位里"能建文件但删不掉"
- **现象**：新会话用 write 工具建了测试文件，后面删不掉（没有审批通道）。
- **根因**：受限档位的写 vs 删权限不对称。
- **做法**：演练/受限会话**不要用 shell 建文件**；文件清理交给全权会话；接手文档给"自测档位"的固定命令。

### E3 本地文件写不了就当"坏了"
- **现象**：报 `PermissionError`，以为是磁盘或权限出了问题。
- **根因**：沙箱档位限制，不是故障。
- **做法**：文档第一行就教"怎么判断我是什么档位"（写临时目录、试写工作区），并给两种档位各自的工具清单。

## F. 接手与治理（组织能不能长大）

### F1 接手语写成了长文
- **现象**：新会话读完还是不知道先干什么。
- **根因**：接手文档面向"人"，不是面向"要动手的 agent"。
- **做法**：接手语必须给**有序的三十秒清单**（0.0 判档位 → 0.1 体检 → 0.2 收信 → 0.3 认自己 → 0.4 读三份 → 0.5 写卡 → 0.6 收尾），每步给可直接粘的命令与"看到什么算正常"。

### F2 接手文档没被验证过
- **现象**：自以为写清了，新会话卡在第二条。
- **根因**：没人真按文档跑过。
- **做法**：改完接手文档就**真开一个新会话**（headless 也行）只给它这份文档，看它卡在哪；把"卡住=无"当验收标准；演练暴露的问题立刻改文档，不改"新会话的理解"。

### F3 同一个提案被否两次
- **现象**：两小时内两次提"把规则全转 JSON"。
- **根因**：否决只存在于对话里，没落账。
- **做法**：被否的提案进 `_否决\`，一条一个文件（现象/为什么否/现在走什么/再提条件）；再提之前先 grep；提新机制先一句话说清"现在哪里会疼"（写不出说明没疼到该动）。

### F4 子代理派出去回不来
- **现象**：子代理干完，上下文里留着它的会话，慢慢占地方。
- **根因**：没有回收动作。
- **做法**：子代理只做只读审计/核对/查证，只回结论摘要（≤15 行或一张表，带路径行号）；**写库仍由主会话做**；干完确认 inactive → 会话目录移到备份区 → 清临时文件 → 回报写"回收：<id> → <路径>"。

### F5 "顺手做的"最贵
- **现象**：改动范围外的文件顺手改了两行，播报漏了，别的线按旧理解做事。
- **根因**：卡外改动没走确认。
- **做法**：卡外改动先问后动；来不及问就记进「偏差记录」并在播报里点明；账要能对上。
