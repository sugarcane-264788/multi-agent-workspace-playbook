# 多会话协作工作区组织方法 (v0.1.0)

> 面向“单操作者并行使用多个 AI 会话、共享同一资料库”的应用场景，提供一套可实施、可审计的协作工作流，涵盖以下环节：
>
> 1. **任务划分**：为每个会话分配独立工作域（cell），明确其写入边界与职责范围；
> 2. **上下文同步**：会话间以消息通道传递变更摘要（变更内容与路径），避免全文回放带来的上下文冗余；
> 3. **冷启动接入**：提供接手清单（handoff checklist），并以一次真实会话演练验证接入完备性，判据为“卡住 = 无”；
> 4. **并发写冲突控制**：共用区域实行单写者（single-writer）约束，非授权会话仅可提交变更请求，不直接写入；
> 5. **变更可审计**：以文件级台账（ledger）记录时间、动作、路径、文件大小与 SHA-256 摘要，验收阶段逐条校验；
> 6. **人机双轨对账**：叙述性文档（Markdown）面向人类阅读，机器快照（JSON）由脚本生成，经一致性检查（doctor）对账；
> 7. **决策留痕**：以计划卡（plan card）记录变更动因，播报按 A/B 两级区分接口变更与过程记录，被否决提案归档至否决账；
> 8. **收尾标准化**：以固定顺序执行收尾流程（台账 → 索引 → 验收 → 播报 → 快照 → 自检 → 对账），降低流程性误报。
>
> **单轮工作循环**：读取当前状态并检索消息通道 → 编制计划卡并领取任务 → 在既定工作域内实施变更 → 登记台账 → 向相关会话发布变更通知 → 执行收尾流程 → 下一会话依当前状态接手。
>
> **设计原理**：单一写入者模型（single-writer）保证共用资料的一致性；单一事实落点（single source of truth）避免冗余与冲突；生成物不进入人工编辑路径，以保证可重建性；流程步骤存在顺序依赖（索引重建先于验收，反之产生伪失败）。
>
> 项目源于个人实际使用实践：同一工作区内多个会话承担不同职能（日常事务、邮件处理、课程学习、资料维护），职能间存在数据关联。该方法以“分工—接力”为核心，旨在降低会话间重复解释成本，提升长期资料库的可持续维护性。
>
> 文档以中文为主，各 skill 顶部附一句英文简述。
>
> 部署自检：执行 `python starter/mailbox_min.py --selftest`，终端输出 `PASS` 表示运行环境配置正确。
>
> **注意事项与免责声明**
>
> 1. **版本状态**：v0.1.0 属试验性发布，接口、目录与命令可能发生不兼容变更；
> 2. **适用范围**：适用于单操作者、多会话并行、单一长期资料库场景；不覆盖多人协作的权限模型，亦不适用于要求强一致性的生产系统；
> 3. **平台约束**：示例在 Windows / PowerShell 环境验证，类 Unix 平台需自行适配路径分隔符与命令语义；
> 4. **数据安全**：单写者约束属纪律性约定而非强制机制，启用前应完成备份，误删、覆盖等后果由使用者承担；

## 问题定义

单操作者可并行运行 3–7 条 AI 会话（分别承担日常事务、邮件处理、课程学习与资料维护等职能），这些会话共享同一批文件。在缺乏协作约束时，常见失效模式包括：

- **事实冗余**：同一事实分散记录于多份文档，修改不同步，后续读者无法判定权威来源；
- **变更不可见**：某会话修改共用文档后，其他会话仍依据旧版本继续操作；
- **冷启动成本高**：新会话须由人工重新交代阅读清单与命令约定；
- **并发覆写**：多会话同时修改同一文件，后写者覆盖先写者，且缺乏检测手段。

## 四个核心部件

| 部件 | 定义 | 存放位置 |
|---|---|---|
| **格子（cell）** | 每个会话拥有独立工作域，仅对自身工作域具备写权限；共用区域由指定会话承担唯一写入职责 | `10-主对话/`、`20-学习/`、`30-邮件/`、`40-协作/` |
| **信箱（mailbox）** | 每条会话线一个独立通道，提供 `send` / `digest` / `publish` 三类操作；消息正文仅记录变更内容与路径 | `40-协作/_消息/` 与 `mailbox.py` |
| **名册（roster）** | 记录会话身份、所属线路与工作域；自动生成段为只读，不得手工修改 | `会话名册.md`（AUTO 段） |
| **台账（ledger）** | 每个文件变更登记一行 `ts/action/path/size/sha256/note`，验收阶段逐条比对 SHA-256 | `_计划卡/ledger.tsv` 与 `verify.py` |

此外有两项补充机制用于闭合流程：**机器层快照**（`_machine/*.json`，由脚本生成；会话不直接读取 JSON，而是读取摘要脚本输出）与**播报**（A 级为接口或规则变更，投递至消息通道；B 级为过程记录，仅落盘）。

## 收尾七步（顺序不可颠倒）

```
台账登记 → 重建索引 → 验收（核台账 + 执行校验命令）→ 播报 → 刷新快照 → 自检 → 对账
```

该顺序源于实践：验收环节通常执行自检脚本，而自检包含“索引是否落后”检查；若索引未在验收前重建，则每轮收尾都会产生伪失败。包内提供 `starter/closeout.sh` 骨架。

## 三十分钟部署路径

1. 阅读 `docs/01-设计全景.md`（整体架构与设计权衡）；
2. 执行 `python starter/mailbox_min.py --selftest`，并按 `starter/README.md` 初始化一个实际信箱；
3. 参照 `starter/card-template.md` 编写首张计划卡，参照 `starter/boot-template.md` 编写首份开工语；
4. 将 `starter/closeout.sh` 中的路径替换为本机路径，并完整执行一次。

## 七个 skill（置于 agent 的 skills 目录后自动加载）

| skill | 职责 | English | 不适用场景 |
|---|---|---|---|
| `multi-session-workspace` | 多会话共用资料库的治理：工作域、一箱一线、名册、播报 | Shared-workspace governance for several parallel agent sessions | 仅单条会话时无需引入信箱 |
| `session-handoff` | 新会话冷启动：三十秒清单 + 真实演练，判据为“卡住 = 无” | Make a cold session productive in 30 seconds, verified by a real dry run | 不应以复制全文代替交接 |
| `card-ledger-workflow` | 变更留痕：计划卡、台账、SHA-256 验收、收尾七步 | Plan card + ledger + sha256 acceptance, so every change is auditable | 单行改动无需开卡 |
| `layered-self-check` | 四层自检：结构、一致性、机器层、真实会话演练，含伪失败判读 | Four-layer self-check, including how to tell a fake failure from a real one | 不得以自检替代实际运行 |
| `human-machine-dual-track` | 人读 Markdown、机读薄快照：先定 schema，生成物不手改，doctor 对账 | Markdown for humans, thin JSON snapshots for machines, reconciled by a doctor | 不应让会话直接硬读 JSON |

| `delegate-and-reclaim` | 审计核对先派子代理、只回收结论；完成后回收会话并报告路径 | Delegate read-only audits, get conclusions back, then reclaim the subagent | 写库操作不应交给子代理 |

## 包内其他内容

- `starter/`：可运行的 80 行信箱实现（`mailbox_min.py`，含 `--selftest`）、计划卡模板、开工语模板与收尾脚本；
- `evals/`：每个 skill 3 条正例与 2 条反例判定用例，供修改描述后进行回归核验；
- `sync_skills.py`：将 `skills/` 同步至 agent skills 目录（`AGENT_SKILLS_DIR`），`--check` 仅核对不写入；
- `scrub_check.py`：发布前自检，确保不泄露绝对路径、真实编号与内部业务名称；
- `docs/`：`01-设计全景`（架构总览）/ `02-经验清单`（30 条“现象 → 根因 → 做法”）/ `03-模板集`（可直接引用的文本）/ `04-落地清单`（从零搭建与不适用条件）。

## 适用范围与边界

- **适用**：单操作者、多条会话并行、一份长期资料库（文档规模数十至数百）；
- **不适用**：单会话小规模项目（一份 README 加一个索引脚本即可）；多人协作（本包不涉及权限模型）；要求强一致性的生产系统；
- 各条规则均标注其对应的失效模式；建议依据当前实际痛点选择性引入，不应全量照搬。
